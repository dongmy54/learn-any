# 测验会话示例

以下是一个完整的知识测验会话示例，以"JavaScript 闭包"为测试主题，展示 `knowledge-quiz` 技能的执行流程与输出格式。

> 本示例共 6 题：**5 道选择题 + 1 道简答题**，覆盖核心概念 / 高频场景 / 易错点三个维度。

## 一、出题与作答过程（逐题循环）

### 第 1 题（选择题 · 核心概念）

调用 `AskUserQuestion` 工具让用户作答：

- **question**：下面关于"闭包"的描述，哪一项是正确的？
- **options**：
  - 闭包是指函数执行完后，其内部变量会立即被回收
  - 闭包是指一个函数能够访问其词法作用域中的变量，即使在该作用域外被执行
  - 闭包只能访问全局变量，不能访问局部变量
  - 闭包是 ES6 才引入的新语法

（工具暂停，等待用户选择）

**用户选择**：第 2 项

**即时反馈**：✅ 完全正确，抓住了"访问词法作用域变量 + 作用域外仍可执行"两个关键点。

### 第 2 题（选择题 · 高频场景）

调用 `AskUserQuestion` 工具：

- **question**：
  ```
  for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0);
  }
  ```
  以上代码输出是？
- **options**：`0 1 2` / `3 3 3` / `0 0 0` / `报错`

**用户选择**：`3 3 3`

**即时反馈**：✅ 正确！这是闭包 + `var` 变量提升的经典坑。

### 第 3 题（选择题 · 高频场景）

调用 `AskUserQuestion` 工具：

- **question**：
  ```
  function counter() {
    let count = 0;
    return () => count++;
  }
  const a = counter();
  const b = counter();
  a(); a();
  console.log(b());
  ```
  以上代码输出是？
- **options**：`0` / `1` / `2` / `3`

**用户选择**：`2`

**即时反馈**：❌ 再想想，`a` 和 `b` 各自持有一份独立的 `count`，互不影响。复盘细讲。

### 第 4 题（选择题 · 易错点）

调用 `AskUserQuestion` 工具：

- **question**：第 2 题中，把 `var` 改成 `let` 后输出变成 `0 1 2`，其根本原因是？
- **options**：
  - `let` 让变量变成了常量
  - `let` 具有块级作用域，每次循环迭代都创建一个新的 `i` 的绑定
  - `let` 让 `setTimeout` 同步执行了
  - `let` 会自动重置变量

**用户选择**：第 1 项（`let` 让变量变成了常量）

**即时反馈**：❌ 不对哦，`let` 不是常量（常量是 `const`）。复盘时讲清真正原因。

### 第 5 题（选择题 · 易错点）

调用 `AskUserQuestion` 工具：

- **question**：关于闭包与内存，下面哪种说法正确？
- **options**：
  - 只要用了闭包就一定会内存泄漏
  - 闭包引用的变量在其不再被需要时仍可能不被回收，需注意不必要的长期持有
  - 闭包引用的变量永远不会被回收
  - 闭包和内存管理完全无关

**用户选择**：第 2 项

**即时反馈**：✅ 正确，区分了"设计上保留"和"意外的内存泄漏"。

### 2. 错题详解

**Q3（选择题 · 高频场景）—— 错误**

- 原题：见上方（`counter()` 创建两个独立计数器 `a`、`b`）
- 你的答案：`2`
- 正确答案：`0`
- 解析：每次调用 `counter()` 都会执行一次函数体，生成一份**全新的、独立的** `count = 0`。因此 `a` 和 `b` 各自闭包了不同的 `count` 变量，互不影响。`a()` 调了两次操作的是 `a` 自己的 `count`；而 `b()` 第一次调用，操作的是它自己那份全新的 `count`，所以返回 `0`。
- 误区：误以为两个计数器共享同一个 `count`，把 `a` 的累加算到了 `b` 头上。这正是"闭包 = 携带独立作用域"的典型坑。

**Q4（选择题 · 易错点）—— 错误**

- 原题：`var` 改 `let` 后输出变为 `0 1 2` 的根本原因
- 你的答案：`let` 让变量变成了常量
- 正确答案：`let` 具有块级作用域，**每次循环迭代都创建一个新的 `i` 的绑定**
- 解析：`const` 才是常量，`let` 不是。`let` 的关键在于块级作用域——循环体每迭代一次，就会创建一个新的、独立的 `i`，每个回调闭包捕获的是各自那次迭代的 `i`，所以输出 `0 1 2`；而 `var` 只有一个函数级变量，三次循环共享同一个 `i`，回调执行时它早已变成 3。

**Q6（简答 · 部分正确）**：概念抓住了"访问外层作用域变量"、用途"封装私有变量"也对。但定义漏了两个关键点——① 闭包是"函数 + 它创建时的词法环境"的整体；② 闭包让外层变量在函数返回后依然存活（不会被回收）。用途除封装私有变量外，还可提"模块化""回调/定时器携带状态""防抖节流"等。

### 3. 知识掌握画像

- 🟢 **核心概念**（基本掌握）：能识别闭包定义、知道典型用途（Q1 全对、Q6 部分对）
- 🟡 **高频场景**（一半一半）：认得 `var + setTimeout` 经典坑（Q2 对），但对"多个闭包各自独立"判断失误（Q3 错）
- 🔴 **易错点**（最薄弱）← **重点关注**：对 `let` 块级作用域的本质（Q4）理解不到位；闭包与内存的关系掌握尚可（Q5 对）

### 4. 学习建议

针对最薄弱的"易错点"维度，建议：

1. **吃透"每次函数调用产生独立作用域"**：自己写 3 段类似 Q3 的代码，手动推演每个闭包各自持有哪些变量，再运行验证。
2. **区分 `var` / `let` / `const` 的作用域与语义**：重点理解 `let` 的"每次迭代新绑定"，这是 Q4 这类题的核心。
3. **动手实现经典闭包模式**：模块模式（IIFE）、计数器、防抖/节流，边写边问自己"这里谁闭包了谁"。
4. **配套资源**：可用本库的 `concept-extract` 技能重新提炼闭包核心概念，或用 `practical-case-designer` 做几个闭包实战案例加深理解。
