# 反思报告与进化日志模板

## 一、反思报告模板

输出给用户的反思报告，按以下结构组织：

```markdown
# 🔄 技能反思报告：<技能名>

## 本次调用回顾
一两句话概括本次调用：用户要什么 → 技能做了什么 → 结果如何。

## ✅ 做得好的
- <本次执行中值得保留的做法，1-3 条，没有可省略本节>

## ⚠️ 发现的问题

### 问题 1：<一句话描述>
- **分类**：触发问题 / 流程问题 / 易错点 / 输出问题 / 知识缺口
- **证据**：本次调用中的具体表现（如"用户第 N 次纠正了 xx"、"产出的 xx 与预期不符"）
- **影响**：造成了什么后果（返工/误解/质量下降）

### 问题 2：……

## 🛠 改动方案

| # | 对应问题 | 改动文件 | 改动内容 |
|---|----------|----------|----------|
| 1 | 问题 1 | SKILL.md「工作流程」 | 在第 X 步后增加"……" |
| 2 | 问题 2 | SKILL.md「经验教训」 | 新增条目：[日期] …… |

## 请确认
请选择：**全部落地** / **落地第 x、x 条** / **暂不落地**
```

编写要点：

- 问题数量实事求是，本次调用很顺利就如实说"无明显问题"，只沉淀做得好的经验或直接结束
- 每个问题的「证据」必须指向本次对话中真实发生的事，不写"可能"、"或许"
- 改动方案要具体到"改哪个章节、改成什么"，让用户看一眼就能判断是否同意

## 二、进化日志模板

落地改动后，在目标技能目录下的 `evolution-log.md` 追加：

```markdown
## [YYYY-MM-DD] 第 N 次进化
- **触发场景**：<一句话：哪次调用、暴露了什么问题>
- **改动**：
  - <文件 + 章节>：<改了什么>
- **未采纳**：<用户否决的方案，无则省略此行>
```

文件首次创建时加标题：

```markdown
# <技能名> 进化日志

记录该技能每次自我进化的时间、原因与改动，便于追溯与回滚。
```
