给任何一个"知识点"，逆向画出它从 **学科根 → 大分支 → 小分支 → 这个点** 的层级路径，让用户瞬间看清自己在哪棵知识树的哪个枝桠上，后续可顺着这条路径去做更深入的探索或互联网搜索。

## 核心原则

1. **反向定位**：核心动作是"定位"而非"展开"。从一个具体的点出发，逐层向上回溯到学科根，然后按从粗到细的顺序输出**一条**到达它的路径。
2. **点到为止**：只列出"到达该知识点的那一条路径"，**不要**把同级的兄弟分支也铺开列出来——这是与 knowledge-map 的根本区别。
3. **多树并列**：如果一个术语/关键词可能属于多个不同的知识体系（例如"梯度"在数学和机器学习中各有所指），必须**同时列出多条路径**，并分别给出说明。
4. **简短说明**：每条路径后只跟**一段**让小白也能"秒懂"的说明——讲清楚这个点在该分支里大致在干什么、解决什么问题，不展开成完整教学。

## 工作流程

### 第一步：解析输入

1. 接收用户输入，可能是：单个术语、一个关键词、或一段【文字描述】。
2. 如果输入是一段【文字描述】，先从中提炼出需要定位的核心概念/术语（可能有多个）。
3. 判断该概念是否可能同时属于多个不同的知识领域；若是，记下所有候选领域。

### 第二步：定位知识树路径

1. 对每个候选领域，从学科根开始，逐层向下定位：学科 → 大分支 → 小分支 → …… → 该知识点。
2. **只画到达它的那一条路径**，不展开兄弟分支。
3. 路径层级深度以"能让用户看清归属"为准，通常 3–6 层即可，不必追求无限细分。

### 第三步：组织输出

1. 按照【输出结构】组织：路径在前，简短说明在后。
2. 多领域时，按【输出结构】中的标号方式分别列出多条路径。
3. 如果完全无法定位（极罕见），诚实告知用户并请其补充上下文，不要硬猜。

## 输出

- **格式**：直接在对话中以 Markdown 输出，**不落盘**
- **【输出结构】**：
  - **路径表示**：用 `/` 串联层级，例如 `数学 / 高等数学 / 最优化 / 梯度下降`
  - **说明**：每条路径下方跟**一段**简短说明（2–4 句），讲清这个点在该分支里大致在干什么
  - **多知识树**：当一个术语跨多个领域时，用 `【树1】【树2】……` 分别标号，各自给路径 + 说明

完整输入输出示例参考 [examples.md](./examples/examples.md)

## 自检

完成技能描述后，请自检：

1. ✅ 是否包含 frontmatter（name 和 description）
2. ✅ 是否包含概述（一句话说明"反向定位"的目标）
3. ✅ 是否包含核心原则（编号列表，每条以加粗关键字开头）
4. ✅ 核心原则是否明确强调了"只列到达路径、不铺开兄弟分支"和"多树并列"

## 绝对不能做的事

1. **不要**把同级兄弟分支铺开列出——只保留到达该知识点的单条路径。
2. **不要**把简短说明展开成完整教学——本技能是"指路牌"，不是"教科书"；深度讲解应交给 `quick-overview`、`concept-extract` 等其他技能。
3. **不要**在存在多个知识树可能性时只给一条——必须都列出来。
4. **不要**堆砌晦涩术语或照搬百科式定义——说明必须对陌生用户友好、能形成直觉。
5. **不要**在判断不准时强行编造路径——诚实说明并请用户补充上下文。
