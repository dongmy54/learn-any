根据用户提供的需求描述或已有技能内容，生成或优化符合标准格式的 Claude Code 技能（Skill），确保技能条理清晰、职责明确，AI 可无歧义地理解并执行。

## 核心原则

1. **理解优先**：在生成或优化技能前，必须充分理解用户的意图和需求。对于优化已有技能的请求，先深度剖析其现有内容与不足。如果信息不够清楚，必须主动向用户询问，使用 `AskUserQuestion` 工具提供选项，用户也可输入自定义内容。
2. **结构规范**：生成的或优化后的技能必须严格遵循【技能标准结构】，确保每个模块完整、清晰。
3. **职责明确**：技能中的每一条指令和职责都必须无歧义，AI 读后应能准确理解"做什么"和"怎么做"。
4. **保留与增强**：在优化已有技能时，必须保留其原有的核心功能与应用场景，严禁擅自删除有用逻辑，而是通过重构使其逻辑更严密、结构更符合规范。
5. **示例分离**：技能中的示例文件应单独存放于 `examples/` 目录下，在主 SKILL.md 中以相对路径引用，不要将大段示例内嵌于主文件。
6. **引用机制**：在文档中使用【xx】标记进行内部引用，然后在适当位置对【xx】进行详细说明，以保证行文逻辑顺畅。
7. **简明扼要，高信息密度**：在不丢失信息准确度的情况下，尽可能保持简明扼要，去除冗余描述，确保整个 skill 文档的可读性和信息密度。

## 技能标准结构

一个标准技能由以下模块组成，各模块说明如下：

### ① Frontmatter（必须）

位于文件最顶部，使用 `---` 包裹的 YAML 格式：

```yaml
---
name: <英文名称>
description: <中文描述：用途 + 自动触发场景>
---
```

- **name**：技能的英文标识名，使用小写字母和连字符（如 `quick-overview`、`concept-extract`）
- **description**：用中文简要描述技能的用途以及自动触发场景，让 AI 知道何时应调用此技能,描述必须要简明扼要，不要冗长

### ② 概述（必须）

紧跟 frontmatter 之后，用一段话（1-3 句）概括技能的核心目标和定位。这是技能的"一句话介绍"，让 AI 立刻理解这个技能是做什么的。

### ③ 核心原则（必须）

以编号列表形式列出技能应遵循的核心职责，格式为：

```markdown
## 核心原则

1. **关键字**：详细描述这条核心职责
2. **关键字**：详细描述这条核心职责
3. **关键字**：详细描述这条核心职责
```

- 每条以编号开头
- 关键字加粗，后跟"："，再接详细描述
- 核心原则用于约束 AI 的行为边界和优先级

### ④ 工作流程（按需）

描述技能执行的步骤流程，使用有序层级结构：

```markdown
## 工作流程

### 第一步：xxx
1. 具体操作说明
2. 具体操作说明

### 第二步：xxx
1. 具体操作说明
2. 具体操作说明
```

- 工作流程不是必须的，根据技能复杂度判断是否需要
- 如果添加，必须保证步骤清晰、逻辑连贯，让 AI 能按步骤执行
- 每个大步骤下可以有小的子步骤
- 步骤中可使用【xx】引用，后续对引用进行说明

PS：对于太过复杂的工作流程，可以使用markdown流程图的方式进行描述

### ⑤ 自检（按需）

在技能描述的最后，添加一个自检部分，确保技能描述符合所有要求：

```markdown
## 自检

在完成技能描述后，请自检以下内容：

1. ✅ 是否包含 frontmatter（name 和 description）
2. ✅ 是否包含概述（一段话概括技能目标）
3. ✅ 是否包含核心原则（编号列表，每条以关键字开头）
```

### ⑥ 输出模块（按需）

描述技能生成的输出内容，包括：

```markdown
## 输出

- **格式**：输出的文件格式（如 markdown）
- **命名**：文件命名规则（如 `{主题}概念提取.md`）
- **位置**：文件存储位置（如项目 `tmp` 目录下）
- **内容结构**：输出内容应遵循的结构要求
```

如有示例，在输出模块中以相对路径引用：

```markdown
示例参考 [example.md](./examples/example.md)
```

### ⑦ 绝对不能做的事（按需）

约束 AI 的行为边界，防止越界操作：

```markdown
## 绝对不能做的事

1. 不要 xxx
2. 不要 xxx
3. 不要 xxx
```

说明：
在某些场景下，**如果使用上面的【技能标准结构】还不够或者不能清晰的阐述skill的功能，可以按需适量添加一些额外的模块结构**。

## 工作流程

### 第一步：收集与分析需求（创建/优化）

1. **接收需求**：接收用户提供的文本描述、指令或已有的技能文件内容。
2. **识别场景**：分析用户意图是**创建新技能**还是**优化已有技能**：
   - **若是优化技能**：读取并分析该已有技能的结构和内容，诊断其不足（如：是否缺失 frontmatter/概述/自检、核心原则是否采用加粗关键字、步骤是否有歧义、是否内嵌了大段示例、文字是否冗余等）。
   - **若是创建新技能**：分析需求是否包含足够信息（用途、触发场景、输入、期望输出、特殊约束等）。
3. **澄清疑惑**：如果关键信息不足或优化方向不明，使用 `AskUserQuestion` 工具向用户提问澄清，收集到足够信息后才进入下一步。

### 第二步：设计或重构技能结构

1. **结构对齐**：对照【技能标准结构】，确定新技能需要包含哪些模块，或对已有技能规划模块的补齐和调整。
2. **元素推演**：
   - **Frontmatter**：确定或优化 `name`（全小写连字符）和 `description`（简明、指明触发场景）。
   - **核心原则**：总结并提炼 3-5 条核心原则，确保每条以编号开头，采用“**关键字**：详细描述”格式。
   - **工作流程**：优化或编写步骤，确保清晰连贯、无歧义。
   - **绝对不能做的事**：提炼约束 AI 行为边界的硬性规则。
3. **示例提取**：分析技能是否包含示例内容。若原技能中内嵌了大段示例，规划将其提取并分离。

### 第三步：写入或重构技能文件

1. **修改/创建主文件**：
   - 创建新技能：在 `.claude/skills/<技能英文名>/` 目录下创建 `SKILL.md`。
   - 优化已有技能：直接修改已存在的 `SKILL.md`，使用更优美的结构、更高的信息密度进行重写。
2. **分离示例文件**：若有示例，在 `examples/` 目录下创建或移动示例文件，并在主 `SKILL.md` 中以相对路径引用。
3. **统一引用标记**：确保文档中使用【xx】内部引用机制，并在后文妥善说明。

### 第四步：全面自检

1. 检查新生成或优化后的技能是否完整覆盖了需求，是否遵循了【技能标准结构】。
2. **核心检查（针对优化）**：
   - 确保原技能的**所有核心功能与有用逻辑都没有被丢失**。
   - 检查描述文字是否已被去粗取精，信息密度是否显著提升。
   - 检查格式是否完美规范（编号、加粗关键字、引用标记等）。
3. 如果发现任何问题，立即修正直到通过自检。

## 输出

- **格式**：Markdown 文件
- **主文件**：`.claude/skills/<技能英文名>/SKILL.md` （创建新技能或就地重构优化已有技能）
- **示例文件**：`.claude/skills/<技能英文名>/examples/` 目录下
- **内容结构**：严格遵循【技能标准结构】

完整示例参考 [example-skill.md](./examples/example-skill.md)

## 绝对不能做的事

1. 不要在用户需求或优化目标不明确时强行操作，必须先通过 `AskUserQuestion` 澄清。
2. 不要将大段示例内容直接内嵌于 SKILL.md 主文件中，示例必须分离到 `examples/` 目录。
3. 不要省略 frontmatter 中的 `name` 和 `description` 字段。
4. 在优化已有技能时，**绝对不能删除或削弱原技能已有的有用业务逻辑**；只能做结构性重构、规范化格式和提升可读性。
5. 不要使用模糊、有歧义的表述编写工作流程和核心原则。
