# 技能标准结构模板

一个标准技能由以下模块组成。①②③ 为必须模块，其余按需添加。

## ① Frontmatter（必须）

位于文件最顶部，使用 `---` 包裹的 YAML 格式：

```yaml
---
name: <英文名称>
description: <中文描述：用途 + 自动触发场景>
---
```

- **name**：技能的英文标识名，使用小写字母和连字符（如 `quick-overview`、`concept-extract`）
- **description**：编写规范见主文件【description 编写规范】

## ② 概述（必须）

紧跟 frontmatter 之后，用一段话（1-3 句）概括技能的核心目标和定位。这是技能的"一句话介绍"，让 AI 立刻理解这个技能是做什么的。

## ③ 核心原则（必须）

以编号列表形式列出技能应遵循的核心职责：

```markdown
## 核心原则

1. **关键字**：详细描述这条核心职责
2. **关键字**：详细描述这条核心职责
```

- 每条以编号开头，关键字加粗后跟"："，再接详细描述
- 核心原则用于约束 AI 的行为边界和优先级，一般 3-5 条
- 硬性约束用"必须 / 绝不"，偏好建议用"优先 / 尽量"，轻重分明

## ④ 工作流程（按需）

描述技能执行的步骤流程，使用有序层级结构：

```markdown
## 工作流程

### 第一步：xxx
1. 具体操作说明
2. 具体操作说明

### 第二步：xxx
1. 具体操作说明
```

- 简单技能（一步到位的转换/生成）**不需要**工作流程，硬加反而增加噪音
- 如果添加，必须保证步骤清晰、逻辑连贯、可直接执行
- 存在分支时明确分支条件（如"若 A 则…；若 B 则…"），互斥分支要注明"N 选 1"
- 步骤中可使用【xx】引用，后文对引用进行说明
- 对于太过复杂的工作流程，可以使用 markdown 流程图 / ASCII 图描述

## ⑤ 输出模块（按需）

描述技能生成的输出内容：

```markdown
## 输出

- **格式**：输出的文件格式（如 markdown），或声明"直接对话输出、不落盘"
- **命名**：文件命名规则（如 `{主题}概念提取.md`）
- **位置**：文件存储位置（如项目 `tmp` 目录下）
- **内容结构**：输出内容应遵循的结构要求
```

如有示例，在输出模块中以相对路径引用：

```markdown
示例参考 [example.md](./examples/example.md)
```

## ⑥ 绝对不能做的事（按需）

约束 AI 的行为边界，防止越界操作：

```markdown
## 绝对不能做的事

1. 不要 xxx
2. 不要 xxx
```

- 只写真正会导致失败/越界的硬约束，不要把普通建议写进来稀释效力
- 常见来源：容易跑偏的行为、与相邻技能的职责边界、用户明确的禁区

## ⑦ 自检（按需）

在技能描述的最后添加自检清单，供 AI 执行完技能后核对：

```markdown
## 自检

完成后请自检：

1. ✅ 是否覆盖了 xxx
2. ✅ 输出是否符合【输出】模块要求
```

- 自检项应针对**该技能最容易出错的点**定制，而非套用通用格式检查

## 扩展说明

如果以上标准结构不足以清晰阐述 skill 的功能，可按需适量添加额外模块（如"核心概念"、"使用示例"、"环境准备"等），但必须服务于"AI 能否无歧义执行"这一目标。
